# Research — what to grab from other agent IDEs

Prioritized checklist of every find from the two deep-dive analyses. Source docs:

- [`HERDR_LEARNINGS.md`](./HERDR_LEARNINGS.md) — Rust terminal multiplexer with agent state detection across 14 CLIs
- [`VIBEYARD_LEARNINGS.md`](./VIBEYARD_LEARNINGS.md) — Electron IDE wrapping Claude/Codex/Gemini with embedded browser + element inspector

Items are grouped into four quadrants by impact (how much this improves Spark) vs effort (how long to ship). Within each quadrant, sorted by priority — highest first.

**Impact scale**
⭐ minor · ⭐⭐ nice · ⭐⭐⭐ meaningful · ⭐⭐⭐⭐ major · ⭐⭐⭐⭐⭐ transformative

**Effort scale**
🕐 tiny · 🕐🕐 small · 🕐🕐🕐 medium · 🕐🕐🕐🕐 big · 🕐🕐🕐🕐🕐 architectural rewrite

`[H]` = from herdr · `[V]` = from vibeyard · `[H+V]` = both sources converge on the same idea

Tick each box as it ships.

## 🚀 Quick wins — high impact, low effort (do now)

- [x] **Per-agent regex table for state detection** `[H]` — ⭐⭐⭐⭐⭐ / 🕐 — Every coding CLI prints recognisable text when it's thinking ("esc to interrupt"), waiting for permission ("do you want to proceed?"), or done. herdr has hand-tuned tables of these strings for 14 different agents. Copy the whole table into Spark so we can tell what an agent is doing just by reading what it printed — no API hooks needed.
- [x] **`seen` flag + workspace attention rollup** `[H+V]` — ⭐⭐⭐⭐⭐ / 🕐 — Today a finished chat looks the same whether you've checked on it or not. Add one boolean per chat that flips to true the first time you open it, and show "done-unseen" in teal (urgent — finished while you were away) versus "done-seen" in green (already acknowledged). Then roll the most urgent child status up to its parent row so the sidebar tells you at a glance which chat needs you. This is the single biggest UX upgrade for the "walk away and come back" workflow.
- [x] **Bracketed-paste injection helper** `[V]` — ⭐⭐⭐⭐ / 🕐 — A ~20-line helper that writes text into a running CLI's terminal as if the user pasted it, without the CLI confusing the bytes for individual keystrokes. Needed by every feature that programmatically sends a prompt — element inspector, drag-dropped file paths, slash commands, persona injection, the lot.
- [x] **Default xterm scrollback to 50K lines** `[H]` — ⭐⭐⭐ / 🕐 — xterm's stock setting only remembers the last 1000 lines of output. AI agents blow past that in a single turn. One-line config change in `TerminalStack.tsx`, instant win for anyone scrolling back to see what an agent actually did.
- [x] **WebGL renderer for xterm with software fallback** `[V]` — ⭐⭐⭐ / 🕐 — Tell xterm to draw the terminal on the GPU instead of the CPU when possible, with automatic fallback to the slower canvas renderer if WebGL fails. Smoother scrolling and noticeably lower CPU during long agent runs.
- [x] **xterm search addon** `[H]` — ⭐⭐⭐ / 🕐 — Drop in `@xterm/addon-search` and bind Cmd+F to a find-in-terminal overlay. herdr doesn't have terminal search at all, so we beat them on a feature that every coding tool needs.
- [x] **Tab-aware notification suppression** `[H+V]` — ⭐⭐⭐ / 🕐 — Don't fire a system notification or play a sound when the chat that needs attention is the chat you're already looking at. Just check `BrowserWindow.isFocused()` and the active tab ID before alerting. Keeps notifications meaningful instead of noisy.
- [x] **Notification triggers (3-rule policy)** `[H]` — ⭐⭐⭐ / 🕐 — Adopt a simple, predictable rule set: always alert when an agent gets stuck waiting for input, alert on completion only if you're not looking at it, never alert when the state hasn't actually changed. No "idle for N seconds" timers — only fire on real state transitions. Predictability beats cleverness for notifications.
- [x] **Provider capability gating** `[V]` — ⭐⭐⭐ / 🕐 — Different CLIs support different features: Codex doesn't expose cost data, Gemini can't take a system prompt, etc. Add a `<Capability feature="costTracking">…</Capability>` wrapper that automatically hides UI sections when the currently-active provider doesn't support that feature — so we never show buttons that would just produce errors.
- [x] **`fs:readFile` path sandboxing** `[V]` — ⭐⭐⭐ / 🕐 — Restrict file-read IPC calls to an allowlist of project directories plus known CLI config folders. Defense in depth: if a webview ever gets compromised by a malicious page, it can't read arbitrary files off the user's disk.
- [x] **`before-input-event` → host shortcuts** `[V]` — ⭐⭐⭐ / 🕐 — When the user's focus is inside the embedded browser, Cmd+P / Cmd+T and other app shortcuts normally get swallowed by the page. Hook into the webview's `before-input-event`, reconstruct the keystroke as a synthetic KeyboardEvent, and forward it to our shortcut manager so app-wide keybindings keep working everywhere.
- [x] **Coalesce PTY resize events** `[H]` — ⭐⭐ / 🕐 — Right now every browser-window resize tick fires a fresh terminal resize. Add tiny dedup logic — if the new `(rows, cols)` matches the last one we sent, skip; debounce the rest by ~16ms (one frame). Stops a flood of wasted work during window drags.
- [x] **Static red for blocked, spinner only for working** `[H]` — ⭐⭐ / 🕐 — Counter-intuitive UX rule herdr nailed: don't pulse the "blocked" indicator, keep it steady red. Only animate the spinner for "working". Pulsing everything makes nothing feel urgent; a steady red dot reads as gravitas. CSS-only change.
- [x] **Zoom mode preserves ratios** `[H]` — ⭐⭐ / 🕐 — When the user "zooms" a pane (fullscreens it), don't actually restructure the layout — just hide the other panes. On unzoom, the original split ratios come back exactly as they were. Simpler code, no layout glitches.
- [x] **Shift-click reload = `reloadIgnoringCache`** `[V]` — ⭐ / 🕐 — One-line tweak on the browser pane's reload button. Plain click = normal reload, shift-click = hard reload that bypasses cache. Every browser power user expects this.

## 🏗️ Big bets — high impact, real effort (plan carefully)

- [x] **Agent state detection loop** `[H]` — ⭐⭐⭐⭐⭐ / 🕐🕐🕐 — The goldmine. Wire the regex table above into an actual polling system: every 300ms grab the bottom 40 lines of an agent's terminal as plain text, run the per-agent patterns against it, and emit "working / blocked / done" events. Add a 1.2-second debounce on the "Working → Idle" transition so a blank screen between turns doesn't make the indicator flicker, and require two consecutive ticks of the same state before publishing it. This single feature stops the manager from guessing what its workers are doing.
- [x] **Element inspector → AI handoff** `[V]` — ⭐⭐⭐⭐⭐ / 🕐🕐🕐 — The marquee feature. Add an "Inspect" button to the browser toolbar, copy vibeyard's preload script nearly verbatim, and when the user clicks a DOM element capture its CSS selector, visible text, and page URL. Format that into a prompt like `Regarding the <button> at /login (selector: '#submit', text: 'Save'): make it red` and paste it into whichever chat is currently active. End-to-end click-to-edit-with-AI.
- [x] **CLI provider abstraction (Claude/Codex/Gemini/Copilot)** `[V]` — ⭐⭐⭐⭐⭐ / 🕐🕐🕐🕐 — Define one TypeScript interface (`CliProvider`) and write one file per coding CLI implementing it: where to find the binary, what env vars to set, what command-line arguments to build for a new vs resumed session, where its hook config lives, what capabilities it supports. Once this exists, Spark can spawn any of them as sub-agents alongside the OpenRouter manager — and adding a new CLI later is just one new file.
- [ ] **Expand the CLI roster — Aider + the long tail** `[H+V]` — ⭐⭐⭐⭐ / 🕐🕐🕐🕐 — Once the abstraction above lands, port the additional agents herdr already detects: Aider (nobody else supports it yet — first-mover position), Amp, OpenCode, Grok CLI, Droid, Hermes, Pi, Kimi, Kiro, Antigravity, Cline. Each is roughly one day's work — fill the provider file, copy detection rules from herdr, optionally write a hook script. The pitch: be the only orchestrator that speaks every coding CLI.
- [ ] **Daemon split (delegate-and-walk-away survives app close)** `[H]` — ⭐⭐⭐⭐⭐ / 🕐🕐🕐🕐🕐 — Today, every running agent dies the second you close the Electron window. Extract the orchestration code into a separate, detached Node process that owns the PTYs and the run state. The renderer becomes a thin client that connects over a named pipe (Windows) or Unix socket (mac/Linux). Until this lands, "delegate and walk away" is technically a lie — agents only run while you're watching.
- [x] **Hook contract for sub-agents to self-report** `[H]` — ⭐⭐⭐⭐ / 🕐🕐🕐 — Give each spawned agent two env vars — a socket path and a unique pane ID — and let the agent POST `{state: "working|blocked|idle"}` back to Spark over a small JSON-RPC channel. Combine with the tail-text detection above: when an agent reports its state via hooks, that's authoritative; if it doesn't, we fall back to reading what it printed.
- [x] **CLI hook ingestion (free observability)** `[V]` — ⭐⭐⭐⭐ / 🕐🕐🕐 — Don't scrape stdout for events. Instead install small Python hook scripts into each CLI's own config (Claude alone has 26 hook events: session start, tool use, permission requests, cost updates, etc.). The hooks dump JSON into a temp directory; Spark watches the directory with `fs.watch` and turns each new file into an event. Free, accurate telemetry for cost, tool use, errors, and completions across every supported CLI.
- [x] **Draw mode (screenshot annotation)** `[V]` — ⭐⭐⭐⭐ / 🕐🕐 — Companion to the element inspector. User toggles "Draw" in the browser toolbar, sketches on a transparent canvas overlay over the page, then submits. We screenshot the page, save the annotated PNG to a temp file, and embed the file *path* (not the base64 bytes) in the prompt. Keeps prompts small and lets Claude Code use its native image-read tool to open it.
- [x] **Swarm mode (grid of live agents)** `[V]` — ⭐⭐⭐⭐ / 🕐🕐 — Toggle a single chat view into a grid that shows every running agent at once. Math is trivial — `ceil(sqrt(n))` columns. Every tile is a real live terminal, not a thumbnail. Empty cells in the grid show a "+" button to spawn another agent. Add what vibeyard doesn't have: a "broadcast" button that sends the same prompt to every tile at once.
- [x] **PATH reconstruction on spawn** `[V]` — ⭐⭐⭐⭐ / 🕐🕐 — Electron apps launched from Finder or the Dock start with a sparse `PATH` that's missing most of the user's installed tools. On macOS/Linux, source the login shell once at startup (`zsh -ilc 'echo PATH'`) to get the real one. On Windows, read the same info from the registry. Inject the rebuilt PATH into every PTY we spawn. Without this, half the CLI binaries can't be found.
- [x] **Binary resolution probing** `[V]` — ⭐⭐⭐⭐ / 🕐🕐 — When the user picks "Claude Code" from a menu, we need to actually find the `claude` binary on their machine. Probe the common install locations (npm global, nvm, scoop, volta, chocolatey, `/usr/local/bin`), then fall back to `which`/`where`, then `npm prefix -g`. Required infrastructure before the CLI provider abstraction can launch anything reliably.
- [x] **Auto-updater wired to GitHub releases** `[V]` — ⭐⭐⭐⭐ / 🕐🕐 — Drop in `electron-updater` and point it at our GitHub releases. Renderer subscribes to "update available / downloading / ready" events and shows banners. Lets users self-serve updates instead of nagging us. Mostly plug-and-play, around 50 lines.
- [x] **Socket API — let agents shape the workspace** `[H]` — ⭐⭐⭐⭐ / 🕐🕐🕐🕐 — Today, Spark spawns workers but workers can't touch the UI themselves. Open a small JSON-RPC socket the manager hands to its sub-agents, with verbs like `tab.create`, `pane.split`, `terminal.read`, `chat.append`. Workers can now author their own workspace — split a verifier pane next to themselves, read another agent's output to grade it, append a status update to the chat. Turns "manager spawns workers" into "workers build the workspace they need."
- [x] **Cost tracking via OpenRouter usage + price table** `[V]` — ⭐⭐⭐⭐ / 🕐🕐🕐 — Extend the run-store record with token counts and dollar cost. After each OpenRouter API call, multiply the returned `usage` numbers against a hardcoded model-price table. Aggregate per call → per step → per run, and show the total in a status-bar pill so the user always knows what a long autonomous run is costing them.
- [x] **Four-channel notifications (in-app + system + sound + OS-native cues)** `[H]` — ⭐⭐⭐⭐ / 🕐🕐🕐 — When an agent needs attention or finishes, light up multiple channels at once: in-app toast, native OS notification, embedded sound clip (one for "needs you", one for "done"), plus OS-specific cues like a dock badge on macOS and taskbar flash on Windows. Each channel individually toggle-able. Combined with the tab-aware-suppression rule so we don't spam.
- [x] **Session Inspector overlay (Cmd+Shift+I)** `[V]` — ⭐⭐⭐ / 🕐🕐🕐 — A single overlay with tabs for Costs, Events log (raw JSONL), Context Window usage, and Tool Failures. Pure presentation layer — all the underlying data already flows through run-store and the hook ingestion system above. Around 200 lines per tab.
- [ ] **Remote SSH attach** `[H]` — ⭐⭐⭐⭐ / 🕐🕐🕐🕐🕐 — Lets the user connect to a Spark daemon running on another machine: `ssh -T host 'spark-manager --bridge'` plus around 150 lines of bidirectional byte copying. Launch a long autonomous run on a beefier remote box, close your laptop, attach from your phone later. **Blocked on daemon split — needs that to land first.**

## 🎨 Polish — modest impact, low effort (when bored / between bigger work)

- [ ] **Sub-modes with hint bar** `[H]` — ⭐⭐⭐ / 🕐🕐 — When the user enters a modal action like "resize pane mode", show a visible badge in the status bar listing the keys that are currently active (`h/j/k/l` to resize, `esc` to exit). Beats stacking chord shortcuts that nobody remembers.
- [ ] **Per-session webview partition + isolated toggle** `[V]` — ⭐⭐⭐ / 🕐🕐 — By default all browser tabs share cookies. Add an "Isolated" toggle that gives a specific tab its own cookie jar (`persist:spark-browser-iso-<sessionId>`). Useful for testing a logged-in user flow without trashing your real session.
- [ ] **Cross-CLI session handoff via transcript path** `[V]` — ⭐⭐⭐ / 🕐🕐 — When the user switches a chat from one CLI to another mid-conversation, point the new CLI at the old CLI's transcript file on disk instead of trying to copy-paste the history. The new CLI reads the prior context itself.
- [ ] **`gh` CLI shellout instead of Octokit** `[V]` — ⭐⭐⭐ / 🕐🕐 — For anything GitHub-related (PRs, issues, reviews), shell out to the user's local `gh` command instead of importing the Octokit SDK. Inherits the user's existing auth, no token management on our side, no SDK version churn to babysit.
- [ ] **Personas as markdown with frontmatter** `[V]` — ⭐⭐⭐ / 🕐🕐 — Define agent personas (Architect, PM, Code Reviewer, Security Engineer, etc.) as plain markdown files with YAML frontmatter for `id, name, role, description`. The body of the file *is* the system prompt. Best fit for verifiers and specialty workers — not the manager itself, since its prompt is highly structured.
- [ ] **Selection autoscroll hot-zone** `[H]` — ⭐⭐ / 🕐🕐 — When the user drags-to-select inside a scrollable container and the cursor enters the very top or bottom edge, automatically scroll the container while continuing to extend the selection. Common UX pattern, surprising how few apps get it right.
- [ ] **Drag-to-reorder workspaces/tabs** `[H]` — ⭐⭐ / 🕐🕐 — Let users rearrange tabs by dragging them. Add a small movement threshold (don't start the drag until pointer has moved ~5px) so click-to-focus still works without accidentally triggering a reorder.
- [ ] **OSC 52 clipboard forwarding** `[H]` — ⭐⭐ / 🕐🕐 — Some terminal apps emit a special escape sequence (OSC 52) when they want to write to the user's clipboard. Sniff it in the main process before xterm sees it and forward the content to the host clipboard. Without this, agents trying to share text just fail silently.
- [ ] **CWD from /proc not OSC 7** `[H]` — ⭐⭐ / 🕐🕐 — Agents don't reliably tell the terminal what directory they're working in. Read it from the OS directly instead: `/proc/<pid>/cwd` on Linux, `proc_pidinfo` on macOS, `GetFinalPathNameByHandle` on Windows. Lets us show the agent's real working directory in the UI chrome.
- [ ] **Wrapped-line-aware selection extraction** `[H]` — ⭐⭐ / 🕐🕐 — xterm's default `getSelection()` loses wrapped lines, splitting a long output line in half when copied. Use the `SerializeAddon` to extract selections with wrap info preserved so copy-paste of long agent output actually works.
- [ ] **Hot-reload of manager profile / persona configs** `[H]` — ⭐⭐ / 🕐🕐 — When the user edits a JSON config file (`manager-profile.json`, persona files, etc.), re-read it on the fly without needing an app restart. Watch the file with `fs.watch`, validate the new content, swap it in.
- [ ] **Custom close-confirmation flow** `[V]` — ⭐⭐ / 🕐🕐 — Replace Electron's ugly default "you have unsaved changes" browser-style dialog with our own React modal. Intercept the window's close event, send an IPC to the renderer to show our modal, only actually close once the user confirms.
- [ ] **Versioned snapshot + migration** `[H]` — ⭐⭐ / 🕐 — Add a `version: 1` field to every JSON file we persist (`manager-profile.json`, run-store snapshots, etc.). When the schema changes in a future release, tolerate unknown fields and log a diagnostic instead of refusing to load. Saves us from a future "Spark won't open this morning" pain.
- [ ] **No-launch fallback dialog** `[V]` — ⭐⭐ / 🕐 — If no CLI providers validate at startup (Claude not installed, no Codex, no OpenRouter API key, etc.), show a native error dialog listing exactly what's missing instead of silently crashing or showing a confusing blank UI.
- [ ] **New-tab page with localhost quick-links** `[V]` — ⭐⭐ / 🕐 — Empty state of the browser pane shows clickable shortcuts to common dev-server ports (`localhost:3000`, `:5173`, `:8080`, `:4200`). About 10 lines of code, massive quality-of-life for daily dev work.
- [ ] **CLAUDE.md template from vibeyard's** `[V]` — ⭐⭐ / 🕐 — vibeyard's `CLAUDE.md` is unusually well-maintained — architecture overview, components list, IPC namespace map, a "Windows path gotchas in tests" section, even a self-update rule at the bottom. Use it as a template for ours; our current one is lighter.
- [ ] **Centralized platform detection enforcement** `[V]` — ⭐ / 🕐 — We mostly do this already, but codify the rule in CLAUDE.md: never inline `process.platform === 'win32'`, always import `isWin / isMac / isLinux` from the shared `./platform` module. Eventually make it a lint rule.
- [ ] **Render-delay for terminal graphics** `[H]` — ⭐ / 🕐 — Only matters if we ever add support for sixel or iTerm2 image protocols. herdr coalesces image-related rerenders for 20ms after a graphics escape sequence to avoid thrashing on rapid image updates.

## 🤔 Reconsider / defer — lower impact or architectural cost

- [ ] **Path-based BSP tree addressing** `[H]` — ⭐⭐ / 🕐🕐🕐 — herdr addresses every split in its pane tree by walking a `Vec<bool>` from the root (false = first child, true = second child) instead of holding node references. Cleaner for serialization, undo/redo, and surviving reshapes — but our `paneTree.ts` already works fine. Refactor cost > current pain.
- [ ] **Worktree-aware workspaces** `[H]` — ⭐⭐⭐ / 🕐🕐🕐 — One-keystroke creation of a new git worktree as a first-class workspace concept. Nice for ephemeral branch-per-run flows. Not our biggest gap right now.
- [ ] **Agent-resume on restore** `[H]` — ⭐⭐⭐ / 🕐🕐 — Save the agent's CLI-side session ID alongside each pane so app restarts can resume the conversation (`claude -r <uuid>`) instead of spawning a fresh empty session. `run-store.ts` already does most of this — needs the last 20% of wiring.
- [ ] **P2P session sharing (WebRTC + PIN)** `[V]` — ⭐⭐⭐ / 🕐🕐🕐🕐 — Around 600 lines of MIT-licensed code that lets two users share a running session over WebRTC, authenticated by a 4-8 digit PIN. No server required, no infrastructure cost. Read-only by default; making it read-write needs its own permission model.
- [ ] **Binary auto-install over SSH** `[H]` — ⭐⭐ / 🕐🕐🕐 — Pull the matching Spark binary version from a release URL and `cat`-stream it through SSH onto a remote machine on first connect. Only useful once we ship a Spark CLI companion *and* the daemon split — blocked on two prior items.
- [ ] **Kanban board** `[V]` — ⭐⭐ / 🕐🕐🕐🕐 — vibeyard's board is user-initiated (you make cards, agents complete them). Doesn't really match Spark's autonomy thesis where the orchestrator should *create* and *move* cards as it spawns sub-runs. Worth re-evaluating once we have multi-step plans visible.
- [ ] **IPC namespacing refactor** `[V]` — ⭐⭐⭐ / 🕐🕐🕐 — Rename all IPC channels to `window.spark.{namespace}.{method}` (mirrors vibeyard's pattern of 17 grouped namespaces). Cleaner long-term but touches every existing IPC call site, which is invasive for limited near-term payoff.
